# Карта экранов — «Автоматизация КП»

18 экранов, сгруппированы как в навигации стенда. Формат: название, URL, описание, ключевые блоки.
URL указан относительно стенда: `…/prototype/app/stand-app.html#/<route>`.

## Группа «Работа»

### 1. Сегодня — `#/today`
Рабочий стол менеджера: что требует решения прямо сейчас.
Блоки: предупреждение о низкой уверенности распознавания (клиенты чипами, «Показать их»);
4 метрики-перехода (На проверке, Нужен артикул, Ждём поставщика, КП отправлено);
очередь на проверку (таблица/карточки + «Проверить»); «Ожидание» (строки с воздушными
разделителями); мини-статистика дня плитками-сегментами + подсказка горячих клавиш.

### 2. Входящие запросы — `#/requests`
Реестр всех запросов с фильтрами и Excel-подобной таблицей.
Блоки: тулбар (поиск по таблице, фильтры, сохранённые представления, число на странице);
таблица с сортировкой по колонкам, чекбоксами, разворачиванием позиций, инлайн-статусом
и инлайн-ответственным; панель массовых действий; пагинация; карточный вид на ≤860 px.
Состояния: data / loading / empty / error (`?mock=`).

### 3. Карточка запроса — `#/request/<id>`
Полный цикл «письмо → позиции → КП → отправка».
Блоки: письмо с подсветкой артикулов; зона позиций (артикул, цена, уверенность, правки);
расчёт с пошлиной 5%; предпросмотр КП по XLS-шаблону с версиями; лента событий;
диалог подтверждения отправки; ИИ-правка письма.

### 4. Воронка — `#/pipeline`
Канбан из 11 колонок со сменой статуса перетаскиванием.
Блоки: колонки со счётчиками и суммами; карточки запросов; чипы статусов на мобильном;
подсветка колонки при наведении. Недопустимый переход отклоняется с пояснением.

### 5. Клиенты — `#/clients`
Клиенты, собранные автоматически по домену почты.
Блоки: экспорт в XLS, объединение дублей; таблица (клиент, домен, запросы, КП, выиграно,
сумма, последний контакт) — **вся строка кликабельна**; карточка клиента со статистикой,
историей запросов и действиями.

## Группа «Этап 2»

### 6. Поставщики — `#/suppliers`
Сводка по поставщикам: запросов отправлено, среднее время ответа, доля отказов.
Блоки: таблица поставщиков; карточка поставщика с цепочками запросов и днями ожидания.

### 7. Календарь — `#/calendar`
Календарь задач и сроков: контроль поставщиков и клиентов, дедлайны КП.

## Группа «Этап 3»

### 8. Спецификации — `#/specs`

### 9. Аналитика — `#/analytics`
Метрики: конверсия, суммы, сроки, доли, динамика, разбивки.

### 10. Рассылка NEWS — `#/newsletters`

### 11. Подключения — `#/connections`

## Пользовательские сценарии

### Happy path — запрос превращается в КП
1. Письмо клиента попадает в систему → распознаются артикулы и позиции.
2. Менеджер открывает «Сегодня», переходит в очередь на проверку.
3. В карточке запроса проверяет позиции, правит артикул и цену, при необходимости спрашивает ИИ.
4. Цена подтягивается из прайсов на Яндекс Диске, добавляется пошлина 5%.
5. Менеджер открывает предпросмотр КП (XLS-шаблон), убеждается в корректности.
6. **Подтверждает отправку** → КП уходит клиенту, событие падает в ленту.
7. Статус перетаскивается в воронке; клиент и поставщики обновляются автоматически.

### Ограниченный сценарий — нет артикула или цены
1. Уверенность распознавания ниже порога → запрос помечается «Нужен артикул».
2. Менеджер открывает позиции; часть строк без совпадения в прайсах.
3. Отправляет запросы поставщикам из карточки, статус → «Ждём поставщика».
4. Запрос появляется в блоке «Ожидание» и в календаре по сроку.
5. Приходит ответ поставщика → цена подставляется, цикл продолжается.
6. Если поставщик отказал — доля отказов обновляется в его карточке.

### Ошибочный сценарий — недопустимое действие и сбой
1. Менеджер пытается перетащить карточку в статус, недоступный по правилам перехода →
   система **не меняет статус** и показывает пояснение с указанием верного пути.
2. Попытка отправить письмо без подтверждения блокируется диалогом (человек в контуре).
3. Сбой источника цены или почты → экран переходит в состояние `error` с кнопкой повтора;
   данные, введённые менеджером, сохраняются локально и не теряются.
4. Роль без прав открывает раздел → отказ в доступе с пояснением.

## Проверка качества

- Экраны проверены на 390 / 768 / 1440 px, светлая и тёмная темы: горизонтального
  переполнения нет, JS-ошибок нет.
- Все интерактивные элементы имеют обработчики; мёртвых кнопок нет.
- Порядок слоёв CSS: `styles.css` → `stand.css` → `premium.css` (тема перекрывает базовую).
