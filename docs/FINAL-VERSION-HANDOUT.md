# Автоматизация КП — карта токенов и компонентов (финальная версия)

Документ для передачи в разработку. Источник истины — `prototype/app/premium.css`
(слой поверх `styles.css` и `stand.css`). Все значения проверены измерением
в браузере на финальной сборке.

Проект: клиент закупает лабораторное оборудование и реактивы за рубежом
и продаёт в России. Система ведёт путь «запрос → КП» с человеком в контуре:
ничего не уходит клиенту или поставщику без подтверждения менеджера.

## 4. Роли

`гость`, `зарегистрированный`, `подписчик`, `Pro`, `модератор`, `админ`.
Каждый маршрут проверяется функцией `roleCan(route)`; при отсутствии доступа
показывается `.err-state` с предложением сменить роль.

## 5. Правила, которые нельзя нарушать

1. **Один экран за раз** для Lovable — никогда «сделай всё приложение».
2. **Никаких хардкодов цветов** вне CSS-переменных. Значения берутся только из токенов.
3. **Mobile-first**: проектируем на 390px, расширяем до планшета и десктопа.
4. **Каждый экран имеет состояния** loading / empty / error.
5. **Человек в контуре**: отправка клиенту или поставщику требует подтверждения менеджера.
6. **Анимации** через Framer Motion: stagger появления, scroll-triggered, hover.
7. **Движение уважает** `prefers-reduced-motion`.
8. **Доступность**: у каждой иконочной кнопки есть `aria-label`, тап-зона ≥32px,
   фокус виден, активный пункт меню помечен `aria-current="page"`.

- 18 экранов × 3 разрешения (1440 / 768 / 390) × 2 темы — 0 ошибок в консоли,
  0 «undefined/NaN», 0 горизонтальной прокрутки, 0 обрезки без многоточия.
- Контраст: 0 нарушений WCAG AA в обеих темах.
- Доступность: 0 кнопок без подписи, 0 тап-зон меньше 32px.
- Токены сверены с эталоном `stand-616-e1-manager.html`: цвета, радиусы, шрифт совпадают.
