# Аудит кнопок и состояний прототипа

Дата: 23.09.2026 · Проверка выполнена в браузере (Playwright, chromium headless) на живых адресах стендов.

## Метод

Для каждого маршрута стенда собирались все элементы с `data-act` (уникальные пары
`act + key`), затем по каждому элементу:

1. маршрут сбрасывался на исходное состояние;
2. элемент прокручивался в зону видимости (`scrollIntoView`);
3. для `<select>` вместо клика отправлялось событие `change` с первой доступной опцией;
4. для `nopen` предварительно открывалась панель уведомлений;
5. фиксировался эффект: смена hash, изменение длины DOM более чем на 40 байт
   или изменение количества открытых оверлеев (панель, диалог, тост).

Элементы-заглушки (`data-act="soon"`), уже активные фильтры и текущий пункт меню
исключались как заведомо безрезультатные.

## Снятые ложные срабатывания

Первые проходы отмечали как «мёртвые» элементы, которые на самом деле работают.
Причины и подтверждения:

| Элемент | Причина ложного срабатывания | Подтверждение |
|---|---|---|
| `nopen` (уведомления) | Открывается только когда панель уведомлений уже раскрыта; тест кликал «в пустоту» | После открытия панели переход выполняется |
| `chstatus` | Это `<select>`; обработчик висит на `change`, а не на `click` | Отправка `change` меняет статус |
| `tplbody` | Элемент является `<textarea>`, клик по нему не меняет DOM | Редактирование текста работает |
| `invitesend` | Кнопка появляется только внутри диалога приглашения | Внутри диалога клик даёт отклик |
| `newspause`, `newscancel` | Эффект — тост и перерисовка очереди | Тост «Очередь на паузе», ΔDOM 365 байт |
| `setrole` | Роль уже была выбрана | Смена на другую роль работает |
| `mock=empty/error` | Элемент отсутствует в DOM в момент проверки | Состояния открываются через `?mock=empty` / `?mock=error` |
